# [Day 2] Interview

### 기존 코드베이스에 새로운 기술이나 도구를 도입했던 경험이 있다면, 어떤 리스크를 고려했고, 이를 어떻게 관리했는지 설명해주세요. 실무 경험이 없다면 팀 프로젝트나 사이드 프로젝트에서 고민했던 사례를 공유해 주세요.
사이드 프로젝트를 진행하면서, 팀원마다 개발 환경이 달라 실행 오류가 자주 발생했던 경험이 있습니다.
이를 해결하기 위해 Docker를 도입해, 어플리케이션 실행 환경을 컨테이너로 표준화했습니다.
개발 환경을 하나의 Dockerfile로 정의하고, 누구든 동일한 명령어로 컨테이너를 실행하도록 했습니다.
도입 초반에는 Dockerfile 작성 및 이미지 용량 최적화 등 작성하는데 어려움이 있었지만, 공식 문서와 커뮤니티를 참고하며 해결했습니다.
또한 docker-compose를 사용해 SpringBoot와 MySQL을 동시에 실행할 수 있도록 구성했습니다.

### 마이크로서비스 혹은 분산 시스템에서 데이터 일관성을 유지하기 위한 전략을 고민하거나 적용한 경험이 있다면 공유해주세요. 규모가 작아도 서비스 간 데이터 처리 흐름을 설계해본 경험이면 충분합니다.
MSA 아키텍처를 직접 경험한 적은 없지만, 사이드 프로젝트에서 서버와 AWS S3간의 데이터 일관성에 대해 고민한 경험이 있습니다.
사용자 프로필 사진 업로드 기능을 구현하면서, S3에 먼저 이미지를 업로드 한 후 해당 key를 DB에 저장하는 구조로 설계했습니다.
이와 같이 설계한 이유는 S3는 데이터베이스 트랜잭션에 포함되지 않은 외부 시스템이기 때문에, 예외 상황에서 데이터 불일치가 발생할 수 있습니다.
예를 들어, S3 업로드에 실패했는데 DB에 key가 저장되면 잘못된 URL이 사용자 정보에 남게 되고, 반대로 S3에는 이미지가 남았지만 DB 저장에 실패한 경우엔 불필요한 리소스가 발생하는 문제가 있습니다.
이를 방지하기 위해 먼저 try-catch 블록 내에서 S3 업로드를 시도하고, 성공한 경우에만 key를 반환하여 DB에 저장하게 했습니다.

물론 이 구조에서도 "S3에 이미지 업로드는 성공했지만, DB 저장은 실패한 경우"가 존재할 수 있지만, DB 저장 실패 시 S3에 이미지 삭제 로직도 추가해서 보완했습니다.
