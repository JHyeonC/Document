### 동시성 문제란 무엇이며, 이를 해결하기 위한 기본적인 전략을 설명해주세요. 실제 운영 환경에 적용한 사례가 있다면 함께 설명해 주어도 좋습니다.
동시성 문제란, 하나의 자원에 여러 스레드가 동시에 접근하여 데이터 정합성이 지켜지지 않는 것을 의미합니다.
멀티 스레드를 사용하는 환경에서 각 스레드가 공유 자원에 동시에 접근하는 상황이라면 경쟁상태(Race condition)가 발생할 수 있습니다.
경쟁상태가 발생하게 되는 원인은 가시성과 원자성을 보장하지 못했기 때문입니다.

[기본적인 해결방법]

1. Volatile

먼저 가시성이란 공유 자원에 반영된 값을 여러 스레드에서 볼 수 있어야하는 것입니다.
하지만 동시성 문제가 발생했을 때, 한 스레드에서 변경한 내용을 다른 스레드에서 보지 못하는 상황이 발생합니다.
왜냐하면 일반적으로 CPU는 성능을 위해 자주 사용되는 값을 CPU cache에 캐싱하게 되므로, 쓰기 작업이 발생했을 때 CPU cache에 반영 후 Main Memory에 후반영합니다.
다른 스레드에서 공유자원을 값을 수정하여 반영했다고 하더라도, CPU cache에 캐싱된 값을 계속 참조하기 때문에 변경된 값을 알지 못하는 것입니다.
이를 해결하기 위해 Java에서는 volatile을 사용하여 CPU cache에 캐싱을 하지 않고, Main memory에서 항상 값을 읽고 쓸수 있습니다.

하지만 Main memory에서만 값을 읽고 쓰는 작업을 수행함으로 원자성 문제는 해결하지 못합니다.

2. Synchronized

synchronized는 자바의 멀티스레드 환경에서 공유 자원에 대한 접근을 제어하기 위해 사용하는 키워드입니다.
내부적으로는 뮤텍스 기반의 모니터 구조를 사용해, 하나의 스레드만 임계 구역에 접근하도록 보장합니다.
동기화 방법에는 뮤텍스와 세마포어가 있는데, 뮤텍스는 락의 소유권을 가진 스레드만 해제할 수 있어 안정적인 반면
세마포어는 소유권 개념이 없어 다른 스레드가 release할 수 있어 동기화 오류 가능성이 높습니다.
이런 문제를 해결하기 위해 등장한 개념이 모니터입니다.
모니터는 락뿐만 아니라 조견 변수까지 포함해, 상호 배제와 스레드간 통신(wait/notify)을 가능하게 합니다.
자바는 이런 모니터 구조를 객체 단위로 추상화해 synchronized, wait(), notify(), notifyAll()로 제공하고 있습니다.
또한 개발자가 직접 관리하지 않아도 되기 때문에, 동기화를 더 간단하고 안정적으로 처리할 수 있는 장점을 가지고 있습니다.

순차적으로 임계염역에 진입하게 되므로 가시성과 원자성 모두 보장합니다.

3. Atomic Type

Atomic Type은 동시성을 보장하기 위해 Java에서 제공하는 Wrapper Class입니다.
AtomicInteger, AtomicLong과 같은 클래스가 패키지에 포함되어 있으며 단일 변수에 대한 원자적 연산을 제공하여 멀티스레드 환경에서 동시성 문제를 해결합니다.
Atomic 클래스 내부에 모든 필드는 volatile 키워드로 선언되어 있어 모든 스레드가 같은 값을 공유할 수 있는 가시성을 보장합니다.
또한 내부적으로 CAS(Compare-And-Swap)을 사용하여 현재 값을 읽고 예상 값을 비교한 후, 동일하면 새로운 값으로 한번에 교체합니다.
이를 통해 하드웨어(CPU) 수준에서 원자적으로 처리되며, 때문에 락 없이도 원자성을 보장할 수 있습니다.
